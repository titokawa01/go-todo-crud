Lesson10 では、それらの処理を整理するための REST API と HTTPメソッド の考え方を学びます。

ここを理解すると、URL だけでなく「どの方法で送られたリクエストか」を見て処理を分けられるようになります。

REST APIとは

REST は、HTTP のルールを使って API を設計する考え方です。

Webアプリでは、ブラウザやフォームから送られてきたリクエストに対して、 どの HTTP メソッドで送られたか を見て処理を分けることがあります。

REST API は難しい専門用語に見えますが、まずは 「GET / POST / PUT / DELETE を使い分ける仕組み」 だと考えると理解しやすいです。

HTTPメソッド

HTTP では、リクエストの種類をメソッドで表します。

  • GET → 取得する
  • POST → 送信する / 作成する
  • PUT → 更新する
  • DELETE → 削除する

CRUD と対応させると、次のように見えます。 


GET    → Read
POST   → Create
PUT    → Update
DELETE → Delete

この対応関係を覚えておくと、コードを読むときに迷いにくくなります。

Goでの実装イメージ

Go では、r.Method を見て処理を分けます。 


func handler(w http.ResponseWriter, r *http.Request) {
	switch r.Method {

	case http.MethodPost:
		// Create の処理

	case http.MethodPut:
		// Update の処理

	case http.MethodDelete:
		// Delete の処理

	case http.MethodGet:
		// Read の処理

	default:
		http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
	}
}

このように書くと、1つの URL に対して複数の処理をまとめて扱えます。

なぜメソッドで分けるのか

同じ URL でも、送られてくる方法が違えば意味が変わります。

たとえば、/tasks という同じ URL でも、次のように分けられます。

  • GET /tasks → 一覧を見る
  • POST /tasks → 新しいデータを作る
  • DELETE /tasks → データを消す
URL と HTTPメソッドを組み合わせると、処理を整理しやすくなります。

フォームとの関係

ブラウザのフォームは、主に GET か POST で送信します。

このフォームから送られたデータは、Go 側で r.Method を見て判定し、 Create の処理へつなげられます。

Delete や Update では、フォーム以外の方法を使うこともありますが、 まずは「メソッドで処理を分ける」という考え方を押さえましょう。

処理の流れ


ブラウザ / フォーム
↓
HTTPリクエスト
↓
Goのhandler
↓
r.Method を確認
↓
GET / POST / PUT / DELETE で分岐
↓
それぞれの処理を実行
↓
画面表示やDB操作へつなげる

この流れを理解できると、次のレッスンでフォーム送信データを受け取るときに、 「どのメソッドで来たのか」を自然に意識できるようになります。

main.go で確認するポイント

main.go では、次の点を探してみましょう。

  • r.Method で処理を分けているか
  • http.MethodGet や http.MethodPost が使われているか
  • メソッドごとに何をしているか
  • 想定していないメソッドをどう扱っているか
まずは「HTTPメソッドを見て処理を切り替える」という考え方に慣れることが大切です。
