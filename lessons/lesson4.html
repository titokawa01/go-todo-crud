ここを理解すると、ブラウザから受け取ったデータを保存したり、 保存済みのデータを取り出したりする準備が整います。

データベースとは？

Webアプリでは、データを保存するためにデータベースを使います。

たとえば ToDo アプリでは、次のような情報を保存します。

  • タスクの内容
  • 作成日時
  • 完了したかどうか
アプリは「データを保存できる」ことで、初めて実用的になります。

まずはDB接続の全体像をつかむ

Go では database/sql パッケージを使ってデータベースを扱います。

このレッスンでは、まず次の2つを押さえます。

  • sql.Open で接続の準備をする
  • db.Ping() で実際に接続できるか確認する

最初から細かく覚える必要はありません。 「接続の準備」と「接続確認」が別になっている、と分かれば十分です。

MySQLに接続する

Goでは database/sql パッケージを使ってDBに接続します。 


db, err := sql.Open("mysql", "root:9999@tcp(localhost:3306)/mermaid")

この文字列は、データベースへの接続情報を表しています。

接続情報は .env ファイルで管理するのが一般的です。 コードの中にパスワードを直書きしないようにしましょう。

接続文字列の意味


ユーザー名:パスワード@tcp(ホスト:ポート)/データベース名
  • root → ユーザー名
  • 9999 → パスワード
  • localhost → DBサーバーの場所
  • 3306 → ポート番号
  • mermaid → データベース名

この形を見慣れておくと、あとで環境を変えても読み取りやすくなります。

接続できたかを確認する

sql.Open は「接続のための準備」をします。 実際にDBへつながるかは、db.Ping() で確認します。 


err = db.Ping()
if err != nil {
	log.Println(err)
	return
}

エラーが出る場合は、次のような点を確認します。

  • MySQL が起動しているか
  • ユーザー名とパスワードが合っているか
  • ホスト名とポート番号が正しいか
  • データベース名が存在しているか
このレッスンでは、まず log.Println(err) で内容を見て、 何が起きているかを落ち着いて確認する習慣をつけます。

なぜ Ping が必要なのか

sql.Open が成功しても、まだ「本当にDBへつながるか」は確定していません。

そのため、db.Ping() を使って実際の接続状態を確認します。

この考え方は、Webアプリのトラブルシュートでも大切です。 「準備ができた」ことと「実際に使える」ことは別だと覚えておきましょう。

処理の流れ


Goアプリ起動
 ↓
DB接続の準備（sql.Open）
 ↓
接続確認（db.Ping）
 ↓
接続できれば次の処理へ
 ↓
SQL実行（次のLesson）

DB接続は、アプリの土台になる処理です。 ここが見えると、あとで Create / Read / Update / Delete を扱うときに理解しやすくなります。

main.go で確認するポイント

main.go では、次の3つを探してみましょう。

  • sql.Open でDB接続の準備をしている部分
  • db.Ping() で接続確認している部分
  • log.Println(err) でエラーを記録している部分
この3つが見つかると、GoでDBを扱う最初の流れが見えます。
